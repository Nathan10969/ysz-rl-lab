# Claude 审核 07｜MLIP 门槛、跨位结论与补齐放行

日期：2026-10-23。依据：CLAUDE06_RESULTS.md、calibration/CLAUDE06_SCIENCE.json、calibration/evidence/Claude06_P2b_independent_verification.json（16 个大胞的逐项能量，我在本机重新计算过）。原始 XML 没有逐个复核。

## 1. MLIP 门槛：通过，评分器放行
- 小胞 Spearman 0.986（同协议 11 项为 0.982），大胞 0.971；两套的 MACE 前三全部落在 DFT 前三，力误差也都达标。
- **我补算了大胞的几项指标**：减去共同偏移后，相对能 RMSE 为 **0.195 eV/胞（约 0.62 meV/原子）**，MAE 0.147，斜率 1.04。只看 MACE 能量最低的 8 个，Spearman 0.95，Kendall τ 0.86。也就是说，低能尾部的排序同样可靠，不是靠随机构型把能量范围拉宽撑出来的。
- **这对实验设计有直接影响**：MACE 的相对能误差约 0.2 eV/胞，远大于 DFT 数值误差（约 0.02）。所以在代理赛道上，**小于约 0.3 eV/胞的提升不能当作真实收益**。最终结论必须以大胞 DFT 终评为准。PLAN 里的 δ 门槛要据此预先登记（建议 δ ≥ 0.3 eV/胞，或用等额 top-k 的 DFT 低能率来比较）。
- 门槛只覆盖这个校准池。训练过程中模型会把分布推向 MACE 认为的低能区，所以每一轮都要从诊断集里抽样做 DFT 单点，盯住代理偏差（PLAN 已有这一项，保留）。

## 2. 数值收敛：其实已经证明了，被 LREAL 偏移掩盖了
S00 的基准是 LREAL=.FALSE./EDIFF=1E-6，高精度变体是 Auto/1E-5，所以 S00 那一行里混进了 LREAL 的系统偏移（Auto−False，三组配对的均值为 −0.0223 eV/胞，跨度只有 0.001）。把这个偏移扣掉：
- ENCUT 650：S00 −0.2835、S04 −0.2798、S08 −0.2842，**跨度 0.0044 eV/胞** ✅
- k333：S00 −0.0031、S04 −0.0025，**跨度 0.0006 eV/胞** ✅

前提是这几个高精度变体都用的是 Auto/1E-5，请 Codex 确认。S08/k333 补跑一次，凑满 3 个点，但它**不阻塞**后续阶段。

## 3. 跨位：小胞上是真实物理，结论成立
- S02 和 S06 都从理想格点出发，DFT 同样发生了两个氧位点的重排（位移约 2.1 Å），**最终空位位置和 MACE 末态完全相同**。末态的 Y–空位关系是 NN=0、NNN=6–7，与文献里"空位倾向于远离 Y、靠近 Zr"的结论一致。
- 结论：初始占位 c → 弛豫后占位 g(c) 是多对一映射，这是体系本身的物理行为，不是 MLIP 造成的假象。**主任务的评分和去重一律按弛豫后的占位来做**（canonical key 取末态），初始占位只当动作空间。这一条要写进训练环境的规格。
- 大胞 L00 在 108 个离子步时超时，最后的 fmax 是 0.053 eV/Å，已经接近收敛。先免费做一次诊断：用第 108 帧映射占位，看是否已经和 MACE 末态一致；然后从这一帧续算到收敛（见放行）。L01 不再从理想格点做，有两个小胞加上 L00 已经足够。

## 4. 停批规则需要修改
这次是 CPU 上 S08/k333 超时，触发取消了 6 个 GPU 作业。规则执行得没错，但设计得太粗：两边分属不同资源池，彼此也没有依赖。**新规则**：失败只停同组中依赖它的作业；超出封顶或出现异常消耗，才停掉整个池。另外记录一下：平台的实际 GPU 配额是 2 卡并发，不是 8。训练阶段的墙钟估算要按 2 卡来算。
