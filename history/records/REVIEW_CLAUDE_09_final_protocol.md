## 1. G2：按预登记执行，终评改为 top-k 全部做完整弛豫
- 四个构型弛豫前后的修正跨度是 0.142 eV/胞，超过预登记的 0.10，所以简化协议不通过。这个结论成立，不事后放宽。
- 细看数据：前三名（B10/B11/B15）之间的修正跨度只有 0.042，拉大跨度的是中间能量的随机构型 B00（−0.556）。越不稳定的结构，弛豫掉的能量越多，这符合物理直觉。因为终评候选本来就集中在低能区，这条门槛偏严，但预登记就是预登记，照办。
- 占位和前三的顺序都没有变；MACE 几何出发，平均 1.45 卡时、36–63 个离子步就能收敛。**这说明 MACE 弛豫末态可以作为 DFT 完整弛豫的好起点**，这一点可以写进论文的方法部分。
- 终评的 DFT 额度（75 个名额约 109 卡时）等正式实验结束、候选冻结之后再报用户批。现在不需要批。到那时先做跨方法的末态去重，名额会少于 75。

## 2. G1：L00 从理想格点出发，DFT 末态和 MACE 不同，要弄清原因（免费诊断）
DFT 弛豫到第 108 帧时，占位还和 MACE 一致；继续弛豫后，空位又重排了一次（NN/NNN 变成 5/14）。有两种可能的解释：
- (a) MACE 的弛豫停得太早：收敛判据较松，或者停在一个平坦区域。这种情况下，MACE 的势能面本身没有问题；
- (b) 两者的势能面在这里确实不同。

**这是 CPU 上的 MACE 计算，几秒钟就能跑完，不占任何 GPU 池**：
1. 从 DFT 末态几何出发做 MACE 弛豫：它在 MACE 下是否也是极小点？
2. 比较 MACE 对两种末态（MACE 末态和 DFT 末态）给出的能量，看谁更低。
3. 用训练环境的正式弛豫协议（BFGS / fmax 0.03 / 300 步），从理想格点 L00 重新做 MACE 弛豫，看能不能到达 DFT 的末态。
4. 比较 DFT 末态的能量和"MACE 末态几何上的 DFT 单点能"。

判读：如果 1–3 显示 MACE 在 DFT 末态同样更低、只是停早了，结论就是"远离平衡的起点，末态取决于弛豫路径；环境里的动作是局部扰动，不受影响"，评分器维持放行。如果 MACE 认为 DFT 末态更高，就要在论文里如实报告：在偏离平衡很远的区域，代理与 DFT 有盆地差异。终评用 DFT 完整弛豫后的末态和能量，本来就能兜住这种情况。

## 4. 训练计划：批准设计框架；物理预算要等 MACE 测速后重新定标
- 谱系四臂加强搜索臂、同一个 SFT 分叉点、末态 key 去重、奖励分量分开记录、full-softmax 采样以保持概率一致、合法率闸门、诊断 DFT 不进入盲评：**这些设计都通过**。
- **主要担心是规模太小**：每个 seed、每轮只有 4 个起点 × G4，也就是 4 个 GRPO 组、128 个动作；只跑两轮。这样的 RL 信号很可能淹没在噪声里，最后得到"无法判断"，等于白花预算。物理封顶（每 arm/seed 480 次弛豫）是在不知道 MACE 速度的情况下拍定的。
- **要求**：MACE 测速出来后，按"每轮 1.5 卡时的时间封顶"反推可以跑多少次弛豫，扩大起点数，目标是每轮 ≥16 个 GRPO 组。各臂的物理封顶同步放大，保持公平。D0 的教师轨迹也按同样比例放大（目前 16 条示范对 SFT 只够学会格式，不够学策略；这也没关系，因为学习主要靠后面的轮次，但需要在计划里写明）。
- 72/84/87/102 卡时这几档封顶，等重新定标之后再报用户批。我会建议先批"核心包加 L1"这一档。
