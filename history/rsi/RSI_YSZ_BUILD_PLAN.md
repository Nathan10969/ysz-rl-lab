# YSZ 上的 RSI：构建计划 v0（2026-10-27 晚）

**用户决定**：在 YSZ 上做 RSI，定位为应用研究：首次把真正的递归改进机制用于 YSZ，并与固定的改进流程做受控比较。不要求发明新的 RSI 算法。设计以 Codex 的 `docs/rsi_decision_2026-10-27/DECISION_DRAFT.md` v0.2 为基础。

## 三层（不能混淆）
| 层 | 是什么 | 谁来改 |
|---|---|---|
| L1 搜索程序 S | 给定起点和物理预算，选择动作序列来降低能量。S0 = 现有的菜单 + 两特征贪心（复现 980–983） | 改进器 M |
| L2 改进器 M | 读档案和开发集成绩，写新的 S 候选，决定用多少预算评估哪些候选，选出下一代 S | 固定组：不改；递归组：M 自己 |
| L3 递归 | M 修改自己的 `improver/`（诊断方法、实验选择和取证规则、预算分配、提示），改后的版本**真正驱动下一代** | 只有递归组可以 |

把 GRPO 训练加长属于 L1 的训练量，不是 RSI。网格 988–996 照常跑，它属于 L1，结果可以作为 S 可用的一个组件。

## 部件
1. **S 接口**：候选是一个 Python 模块，实现 `choose(view, rng) -> k`。必要时也可以加 `menu_size` 等声明。`view` 是只读视图，包含当前占位、合法动作、局部特征计算器、本链的能量历史和剩余预算。S 不能直接接触物理计算和文件。
2. **裁判**（固定，M 不可写）：
   - 在集群上执行 S，执行内容包括：MACE 弛豫协议 v2.2、格点映射、合法性检查、物理预算计数（每个起点最多尝试 32 次动作），并输出指标：V、最好能量曲线、弛豫数、E/F 调用数、卡时。
   - 只回传裁判自己算出的指标，不回传 S 的任何输出。
   - 隔离：运行前做 AST 白名单检查，禁止 import os/sys/subprocess/socket/pathlib/importlib、open/exec/eval 等；运行时装 Python 审计钩子，S 一旦越界就判为无效并记录。这不是严格的安全边界，局限在报告中写明。
   - GPU 作业走 y12q 串行队列和 budget_guard。
3. **改进器运行器**：本机 Claude Code 无头模式（用户 10/27 选定）。
   - 已实测有效的隔离参数：`--safe-mode --restricted --strict-mcp-config --disable-slash-commands --tools Read,Write,Edit,Glob,Grep,Bash --allowedTools "Bash(./tools/<裁判客户端> *)" --permission-mode dontAsk --permission-prompts none --system-prompt <固定文本，记哈希> --model <固定 ID> --max-budget-usd <每次调用上限>`。
   - 实测结果：工作目录外的文件读不到；不在白名单的 Bash 被拒，`&&`、`;`、`|`、`$()`、反引号拼接的命令也都被拒；没有 MCP 和技能；不生成自动记忆；费用按 `total_cost_usd` 记账。
   - 每条谱系一个独立工作区，只放获准资料：S0、工具说明、裁判规则、开发池说明、离线文献包。不放 C01、人工分析、META_LOG、决策稿或我们的对话。
4. **每代流程**（外层编排固定，不属于任何一组可改的范围）：
   - A 阶段：M_t 读 `improver/` 和档案，写 ≤ c 个候选，并为每个候选申请"8 点筛选"或"24 点完整评估"。
   - 编排器经裁判运行这些评估，结果写回档案。
   - B 阶段：M_t 读结果，选出 S_{t+1}。递归组在这一阶段还可以改写 `improver/`，得到 M_{t+1}。
   - 每代都记录 `improver/` 的哈希，以及"哪个改进器版本产生了哪些候选"，以此证明新版本真正接手了下一代。
5. **数据边界**：
   - 开发池用种子 1 的 tune 池和 val24（这些早已是开发数据）。
   - 最终测试起点在所有候选和改进器冻结后才由裁判生成。生成用的秘密种子存在 M 工作区之外，现在只公开它的 sha256。
   - 重置测试：M0 和最终的 M_t 都回到 S0，在新的开发任务上比较。
6. **终点**：在封存起点上，按 DECISION_DRAFT §2.4 的建议，在每个起点固定预算下比较降能。"达到参考质量所需的计算量"作为第二终点，主终点在正式实验前选定。

## 顺序与预算
1. **S 接口和裁判**：先用 CPU 合成物理测试（判据是 S0 的动作序列与 980/982 的贪心路径一致），再在 GPU 上用一次 8 点开发评估测出真实成本。
2. **改进器运行器和编排器**：先用假裁判在 CPU 上跑通两代，用 C01 做框架调试（C01 只是开发案例）。
3. **小试**：2 对谱系 × 2 代，每代 ≤ 2 个候选，8 点筛选，GPU ≤ 8 卡时。改进器按等价费用计，**上限 $50**（用户批准）。模型先用 `claude-sonnet-5-5` 控制费用，正式实验用哪个模型等小试后再定。
4. **正式实验**：规模按小试测出的真实成本和谱系方差来定，参考 DECISION_DRAFT §3.3 的情景，通常需要 42–49 卡时。训练池合计会超过 90 卡时，届时告知用户。
