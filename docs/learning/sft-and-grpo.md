# 从教师示范到组内比较

## SFT：先模仿已经出现过的动作

**监督微调（SFT）**把当前结构作为输入，把教师示范中的动作作为目标输出。它告诉模型“这条记录中的教师选了什么”。教师没有评估的其它动作，不能因此被当成更差的动作。

菜单版本把一条教师动作与 15 个其它合法动作混排，让模型输出教师所在序号。4 份混排让模型不依赖固定序号；它们仍来自同一次物理示范。

代码入口：[sft_rows_v4](../../research/formal12/scripts/formal12_menu.py) 和 [sft_row](../../research/formal12/scripts/formal12_actor.py)。

## GRPO：比较同一起点产生的一组轨迹

项目每组采样 4 条轨迹。**回报**是轨迹里奖励的合计；**优势**表示某条轨迹相对组内平均水平的好坏。项目使用组内中心化并除以总体标准差：

$$A_i = \frac{R_i-\overline{R}}{\operatorname{std}(R_1,\ldots,R_4)}.$$

例如回报 `[0, 1, 2, 1]`，均值为 1，优势约为 `[-1.414, 0, 1.414, 0]`。整组回报相同时，代码给出零优势。

输入是完整的四条回报，`group_advantages` 输出同形状优势。它不会自行更新模型；后续损失函数才用优势改变动作概率。

代码入口：[group_advantages](../../research/formal12/scripts/claude08_grpo.py)。

## 更新时，为什么要保存旧策略和参考策略？

**旧策略**是采样这些动作时的策略，用于计算新旧概率比。**参考策略**固定在指定 SFT checkpoint，用于约束当前策略漂移。两者职责不同。

项目有裁剪概率比和 KL 项。裁剪目标限制局部更新激励；KL 项惩罚偏离参考策略。它们并不保证每轮验证分数上升。实际实验中出现过更新后性能下降。

约束版本只在合法 token 的集合内归一化概率。只有一个 token 可选的位置没有选择自由，对应梯度必须正确处理。

代码入口：[masked_causal_logprobs / one_update_masked](../../research/formal12/scripts/constrained.py)。

## 一个实际教训：优化器本身也有状态

早期元流程发现每次更新重新创建 AdamW。后来加入在同一作业内保留优化器状态的选项，并调整更新频率。第 3 步有弱改善，继续训练没有证明改善能累积。这给出一个需要通过实验验证的假设，而不是“修一个实现细节就一定学会”的结论。

## 参考

GRPO 的原始方法来源是 [DeepSeekMath](https://arxiv.org/abs/2402.03300)。本项目的回合奖励、动作掩码、LoRA 和更新调度是材料搜索任务中的具体实现，复现时应阅读代码与协议，而非只根据算法名称推断行为。
