# 合法动作与有效选择，分别怎样检验？

## 约束解码解决可执行性

项目把合法动作对应的 token 序列组织成树。生成每个 token 时，只保留当前前缀下仍能到达合法动作的选择。

这能保证动作满足接口条件。对这个实验，更进一步的问题是：在所有合法动作中，模型是否更倾向于选择有用的动作？

菜单实验把合法动作列成 16 个选项，每项提供最近邻／次近邻 Y–空位对数的变化。模型输出选项编号。

## 为什么需要两个非 LLM 对照？

- **同菜单随机：**同一状态、种子和步骤产生同样菜单，从中均匀随机选，给出无学习选择器的表现。
- **特征贪心：**按冻结公式 `0.0767 × dNN − 0.0802 × dNNN` 选最低预测分数，检验简单规则已经能做到什么。

两者都要走同样的物理环境、计费和评价路径。不同方法选择不同动作之后，后续状态和菜单会自然分叉；“同菜单”并不表示整条轨迹强行共享同样状态。

代码入口：[choose](../../research/formal12/scripts/formal12_rl.py) 与 [greedy_choice](../../research/formal12/scripts/formal12_menu.py)。

## 分数上升，怎样判断证据强度？

评价指标先在每个起点取四条轨迹的最好降幅，再跨起点平均。不同方法使用相同起点时，可以逐起点相减，这叫**配对比较**。

“± 标准误差”表示这个平均值受有限起点采样影响的大小。它不是每个起点之间的标准差，也不是两倍宽度的 95% 置信区间。

项目的探索规则是配对提高至少 `max(0.10 eV, 1×配对标准误差)`，同时超过随机与贪心。它用于选后续实验，不能代替独立验证。验证池已经参与多次选方案，所以最终确认需要新的起点及多个种子。

复算入口：`python tools/results.py --paired meta_s6_greedy meta_s6_menurandom`。

## 在项目里发生过的更正

旧最佳 LLM 比另一条代码路径的随机游走略高。加入同框架的 menurandom 后，模型优势不再成立。保留这个更正，可以把“什么证据改变了判断”追溯清楚。

同样，“最近邻变化分布接近随机”只能描述这个统计量；它不能证明策略在所有维度上等同随机，更不能证明模型永远学不会物理。
